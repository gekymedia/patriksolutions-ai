# Module 6 — Evaluating Quality & Troubleshooting Failures

**Estimated time:** ~85 minutes · **Lessons:** 4

## Learning objectives
By the end of this module you will be able to:
- Define what "good output" means for your use case (before you judge it).
- Build a small test set and score outputs with a rubric.
- Recognize common AI failure modes and their fixes.
- Debug a misbehaving prompt or assistant systematically.

**No-code module.** Testing uses a simple spreadsheet; no programming required.

---

## Lesson 6.1 — Define "good" before you judge

You can't improve what you can't measure, and you can't measure without a definition. Before testing any AI output, write down what **good** looks like for *this* task — usually 3–5 criteria:

- **Accuracy** — facts correct, nothing invented.
- **Relevance** — actually answers what was asked.
- **Format** — matches the required structure.
- **Tone/voice** — on-brand.
- **Safety** — refuses what it should; no privacy leaks; no harmful content.

**Example — a customer-reply assistant's "good" =**
1. Accurate (uses real policy, no invented prices)
2. Warm and on-brand
3. Under 120 words with a clear next step
4. Refuses to give medical advice / exact personal quotes
5. No private data exposed

Now "is this good?" becomes a checklist, not a vibe. Vague standards produce vague quality; explicit criteria produce reliable quality.

---

## Lesson 6.2 — Build a test set and score it (a simple "eval")

Professionals don't trust an AI tool because it worked once. They **test it on a set of cases** — an **evaluation** (or "eval"). You can do this in a spreadsheet.

**Build a mini eval (no code):**
1. **Collect 10–20 realistic inputs**, including easy, tricky, edge, and "should refuse" cases.
2. Make a spreadsheet: columns = *Input · Expected/Notes · Output · each criterion (pass/fail or 1–5) · Issues*.
3. **Run each input** through your prompt/assistant; paste the output.
4. **Score** against your criteria (Lesson 6.1).
5. **Read the failures** — patterns point to the fix.

**Example scoring row:**
| Input | Output | Accuracy | Voice | Format | Safety | Issue |
|---|---|---|---|---|---|---|
| "Price for 24/7 care?" | [reply] | ✅ | ✅ | ✅ | ❌ | Gave an exact figure — should give a range |

**Two power moves:**
- **Compare versions.** Changed a prompt? Re-run the *same* test set and compare scores. This proves an "improvement" actually improved things (and didn't break something else).
- **AI-assisted grading.** For big sets, have a second AI call grade outputs against your rubric: `Score this reply 1–5 on accuracy, voice, format, safety per these rules: [rules]. Explain each score.` Useful at scale — but **spot-check the grader**; it can be wrong too.

A 15-input spreadsheet eval is the single highest-leverage quality habit in this whole course.

## Lesson 6.3 — Common failure modes (and the fix for each)

Most AI failures fall into a handful of patterns. Learn the fix for each:

| Failure | Looks like | Fix |
|---|---|---|
| **Hallucination** | Confident made-up facts/sources | Ground in documents (RAG); say "not sure/not in docs"; require citations; verify |
| **Format drift** | Mostly-right structure that breaks | Give an exact template; forbid extras; repeat the rule at the end; add "TBD" for missing |
| **Ignoring instructions** | Skips a rule, especially in long chats | Put key rules first *and* last; shorten context; split into steps; restate the rule |
| **Too generic / bland** | Vague, could-be-anyone output | Add role, examples (few-shot), audience, and your voice note |
| **Wrong scope** | Answers things it shouldn't | Tighten scope in system instructions; add "if outside scope, redirect" |
| **Overconfidence** | States guesses as facts | Ask for confidence + "what might be wrong"; require sources |
| **Refusing good requests** | Over-cautious "I can't help" | Add context/clarify intent; rephrase; specify legitimate purpose |
| **Inconsistency** | Different answer each run | Lower variability (set temperature low if the tool allows); use examples; make the prompt more specific |

> **"Temperature"** (a setting some tools/APIs expose) controls randomness: **low = more consistent/predictable**, high = more creative/varied. For reliable business tasks, lower is usually better.

## Lesson 6.4 — Debugging a prompt or assistant, step by step

When something's wrong, don't just re-roll and hope. Diagnose:

1. **Reproduce it.** Find the exact input that fails. You can't fix what you can't repeat.
2. **Isolate.** In a chain, test each step alone to find *which* step breaks. In a single prompt, strip it to the minimum that still fails.
3. **Read what it actually did** vs. what you wanted. Often the instruction was ambiguous, not "the AI is dumb."
4. **Change one thing at a time.** Add a rule, an example, or clearer format — then re-test. Changing five things at once hides what worked.
5. **Ask the AI to help debug:** `This output didn't follow [rule]. Why might that be, and how should I change the prompt?` It's surprisingly good at diagnosing its own misses.
6. **Re-run the whole test set** after the fix — confirm you improved the target case *without* breaking others (regression check).

**Mindset shift:** treat bad output as **information**, not failure. Each miss tells you exactly what rule or example your prompt is missing. Debugging prompts is a skill — and it's mostly patience + changing one thing at a time.

## 🎬 Instructor demonstration script
1. **Write the "good" criteria** for a sample assistant on screen. "Now quality is a checklist."
2. **Build a mini eval spreadsheet** with 6 inputs (incl. an edge + a should-refuse). Run them, paste outputs, score. Point at the failing row.
3. **Diagnose the failure** (e.g., it gave an exact price). Change *one* instruction. Re-run the test set. Show the row now passes and others still pass. "That's a real improvement, proven."
4. **Walk the failure-mode table** quickly, matching one real miss to its fix.
5. **Show temperature** (if the tool exposes it): high vs. low on the same prompt. "Low for reliable, high for brainstorming."

## 🛠️ Hands-on exercise (30 min)
1. Write the **"good" criteria** (3–5) for an assistant/prompt you built earlier.
2. Build a **test set of 10 inputs** (easy, tricky, edge, should-refuse) in a spreadsheet.
3. **Run and score** them against your criteria. Find the failures.
4. **Fix one failure** by changing a single thing; **re-run the whole set** to confirm no regression.
5. Note your assistant's **top 2 weaknesses** and a safeguard for each.

**You're done when** you've improved at least one failing case and confirmed (by re-running the set) you didn't break others.

## ✅ Quiz (with answers & explanations)

**Q1. Before judging AI output, you should first…**
A) Count the words
B) Define what "good" means (3–5 criteria) for the task
C) Ask a friend
D) Change the model
**Answer: B.** Explicit criteria turn "quality" into a checklist.

**Q2. An "eval" is…**
A) A payment
B) Testing the AI on a set of cases and scoring against your criteria
C) A type of prompt
D) A model name
**Answer: B.** A test set + rubric = measured quality.

**Q3. After improving a prompt, why re-run the whole test set?**
A) To waste time
B) To confirm you fixed the target case without breaking others (regression check)
C) It's required by law
D) To use more tokens
**Answer: B.** Prove real improvement, no regressions.

**Q4. Output keeps breaking format in long chats. A good fix is…**
A) Make the chat longer
B) Put key rules first and last, give an exact template, and/or split into steps
C) Ask in another language
D) Nothing can be done
**Answer: B.** Reinforce format, shorten context, step-split.

**Q5. True or false: For reliable, consistent business tasks, a lower "temperature" setting is usually better than a high one.**
**Answer: True.** Low = predictable/consistent; high = creative/varied.
