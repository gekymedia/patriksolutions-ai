# Module 2 — Multi-Step Workflows & Prompt Chaining

**Estimated time:** ~90 minutes · **Lessons:** 4

## Learning objectives
By the end of this module you will be able to:
- Break a complex task into reliable chained steps.
- Pass output from one step cleanly into the next.
- Add checkpoints, branching, and error handling to a chain.
- Decide when to keep it manual vs. automate it (a bridge to Module 5).

**Mostly no-code.** One **⌨️ Optional coding** sidebar at the end shows how chains look in code.

---

## Lesson 2.1 — Why chain? The power of breaking tasks down

Course 2 introduced chaining ("step 1 → step 2 → step 3"). Here's the advanced principle: **small, focused steps beat one giant prompt.**

One mega-prompt ("summarize this, then write an email, then make a checklist, then draft call questions") often does each part poorly, because the model is juggling everything at once. Break it into steps and each one is sharper, easier to fix, and reusable on its own.

**A chain is just:** Step 1 produces output → you feed that into Step 2 → and so on. Each step has its own focused prompt (ideally a template from Module 1).

**Design a chain in three questions:**
1. What's the **final output** I need?
2. What are the **intermediate pieces** required to get there?
3. What's the **right order** (what must exist before the next step can run)?

**Example — "Turn a customer call into a follow-up package":**
1. Transcript → **structured summary** (decisions, needs, objections).
2. Summary → **follow-up email** (addresses their needs).
3. Summary → **internal CRM note** (what to remember).
4. Summary → **proposal outline** (if they're a fit).

Four clean steps, each great at its job, each reusable elsewhere.

## Lesson 2.2 — Passing data cleanly between steps

Chains break when step 2 can't understand step 1's output. The fix: make each step produce **clean, structured output** (Module 1's format control), then hand it over explicitly.

**Two ways to run a chain manually:**
- **Same chat (easy):** keep going in one conversation; the AI remembers prior steps. Good for quick, linear chains. Risk: long chats can get "muddy" or lose focus.
- **Hand-off (reliable):** have step 1 output a clean block (e.g., JSON or a labeled summary), then start the next step by pasting that block as the input. More control; easier to reuse a single step.

**The hand-off pattern:**
```
STEP 1 PROMPT → outputs:
{"needs": [...], "objections": [...], "budget": "TBD"}

STEP 2 PROMPT:
Using this customer profile, write a follow-up email addressing their needs and objections.
PROFILE: {paste the JSON from step 1}
```

**Golden habit:** design step 1's *output* to be exactly what step 2 *needs* as input. When you control both ends, the chain is rock-solid. This is also precisely how automated chains work (Module 5) — you're learning the real pattern by hand first.

## Lesson 2.3 — Checkpoints, branching, and error handling

Real workflows aren't a straight line. Add three things to make chains robust:

**1. Checkpoints (human-in-the-loop).** Mark steps where a person reviews before continuing — especially before anything goes to a customer or gets recorded. In your chain doc: *"⛔ CHECK: human approves email before Step 4."*

**2. Branching (if/then).** Different inputs need different paths. Use a **router** step (Module 1 pattern) to decide:
```
Classify this inquiry as: PRICE / SUPPORT / COMPLAINT / OTHER. Reply with only the label.
```
Then: if COMPLAINT → complaint-reply template + human review; if PRICE → quote template; etc. You're designing decision logic in plain language.

**3. Error handling.** Plan for bad or missing input:
- Add "If the input is missing [X], stop and ask for it" to the step.
- Validate: "Before continuing, confirm the summary contains a budget; if not, flag it."
- Keep a fallback: if AI output looks wrong, the human catches it at the checkpoint.

**Good workflow = happy path + the messy cases.** Beginners build only the happy path; pros plan for the 20% that breaks.

## Lesson 2.4 — Manual vs. automated: when to graduate

You can run a chain **three ways**, increasing in effort and payoff:

1. **Manual chain (you paste between steps).** Best when: the task is occasional, high-judgment, or still being refined. Zero setup.
2. **Semi-automated (saved templates + a checklist).** Your prompt library + a documented order. Best when: frequent but you still want to drive.
3. **Automated (a tool runs the chain on a trigger).** Best when: repetitive, high-volume, clear trigger, stable steps. Setup pays off. (Module 5.)

**Rule:** perfect the chain **manually first**, then automate only the steps that are stable and safe. Automating a half-baked chain just makes mistakes faster. Prove it by hand → then hand it to a machine.

> **⌨️ Optional coding sidebar — what a chain looks like in code**
> Developers run chains with libraries (e.g., Python scripts that call an AI API step by step, or frameworks like LangChain / the LlamaIndex pipeline). The idea is identical: output of one call becomes input to the next, with validation in between. You do **not** need this to pass the course — your no-code chain is the same logic. If you're curious, Module 5 shows the API basics.

## 🎬 Instructor demonstration script
1. **Mega-prompt vs. chain:** ask one giant prompt to do four things (point out the mediocre result), then run the same as a 4-step chain. "Smaller steps, sharper output."
2. **Clean hand-off:** make step 1 output JSON; paste it as step 2's input. "Design the output to be the next step's input."
3. **Add a router:** classify an inquiry, then branch to the right template. "This if/then is decision logic in plain English."
4. **Insert a checkpoint:** "⛔ human approves before send." Explain where and why.
5. **Error handling:** feed a step missing data; show it stopping to ask instead of inventing (because you told it to).

## 🛠️ Hands-on exercise (30 min)
1. Pick a **multi-step task** from your work. Map it: final output, intermediate steps, order.
2. Build it as a **manual chain** — a focused prompt per step, with clean hand-offs.
3. Add a **router/branch** for at least one decision point.
4. Add a **human checkpoint** and one **error-handling** rule.
5. Run it end-to-end on a real (anonymized) example and note where it needed fixing.

**You're done when** you have a working manual chain with a branch, a checkpoint, and an error rule documented.

## ✅ Quiz (with answers & explanations)

**Q1. Why prefer several small prompts over one giant prompt for a complex task?**
A) It uses less electricity
B) Each focused step produces sharper output and is easier to fix/reuse
C) It's required
D) It's slower on purpose
**Answer: B.** Focused steps = better quality + reusability + easier debugging.

**Q2. The most reliable way to pass data between steps is to…**
A) Hope the AI remembers
B) Have step 1 output clean, structured text that is exactly step 2's input
C) Use voice
D) Start over each time
**Answer: B.** Design the hand-off; control both ends.

**Q3. A "router" step does what?**
A) Translates text
B) Classifies the input so the workflow can branch to the right path
C) Sends emails
D) Stores data
**Answer: B.** Classification → branching (if/then) logic.

**Q4. When should you automate a chain?**
A) Immediately, before testing
B) After it's proven manually and the steps are stable, repetitive, and safe
C) Never
D) Only if you can code
**Answer: B.** Prove by hand first; automate stable, safe, repetitive steps.

**Q5. True or false: A good workflow plans only for the "happy path" where everything goes right.**
**Answer: False.** Pros plan for missing/bad input and add checkpoints — the messy 20%.

- [ ] Mapped: final output, intermediate steps, order
- [ ] Each step has a focused prompt (template)
- [ ] Clean, structured hand-offs between steps
- [ ] At least one branch (router) where needed
- [ ] Human checkpoint before anything customer-facing/recorded
- [ ] Error handling for missing/bad input
- [ ] Proven manually before any automation
