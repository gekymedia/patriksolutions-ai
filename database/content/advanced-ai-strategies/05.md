## Lesson 5.1 — What's an API? (no jargon)

An **API** (Application Programming Interface) is just a **way for two pieces of software to talk to each other** — a defined "order window" one app offers so others can request things from it.

**Analogy:** a restaurant kitchen has a service window. You don't walk into the kitchen; you place an order at the window in the expected format, and the kitchen sends food back. An API is that window: you send a request in the format it expects, it sends a response back. 

- The **AI model has an API**: send it text ("order"), it sends back its answer ("food").
- Your **email tool, spreadsheet, CRM, calendar** — most have APIs too.
- **Integrations** connect these windows so apps work together: "when a form is submitted (one API), send the data to AI (another API), then save the result to a spreadsheet (a third API)."

You rarely touch APIs directly — **no-code tools do it for you**. But knowing the concept explains what's happening when you "connect" apps, and why things like **API keys** and **costs** exist.

## Lesson 5.2 — Build a real AI automation, NO code

Let's make "when X happens → AI does Y → result goes somewhere" real. The no-code tools (from Course 2): **Zapier, Make, n8n** (all have free tiers; third-party, not included in your membership).

**The pattern — every automation has three parts:**
1. **Trigger** — what starts it (new email, form submission, new row, a schedule).
2. **Action(s)** — what happens (ask AI to process, then do something with the result).
3. **Destination** — where the result goes (reply, spreadsheet, chat, doc).

**Worked example — "Auto-summarize new inquiries" (any business):**
1. **Trigger:** a new submission in your contact form (or a new email in a label).
2. **AI action:** send the message to an AI step with a prompt: `Summarize this inquiry in 1 line and classify it as PRICE / BOOKING / SUPPORT / OTHER.`
3. **Destination:** add a row to a Google Sheet (summary + category + timestamp) **and** send you a notification. 

Now every inquiry is logged and triaged automatically — you built a mini system. Many no-code tools have a **built-in AI step** (so you don't even need a separate AI account/key); others let you **connect your own AI account**.

**Building it (same shape in any tool):** pick the trigger app → connect it → add an AI/processing step with your prompt → add the destination step → **test with one real example** → turn it on. Start with the free tier and one simple automation.

## Lesson 5.3 — API keys, costs & rate limits (what to know)

When you connect **your own** AI account to an automation (instead of a tool's built-in AI), you'll meet three things:

- **API key:** a secret password that lets a tool use your AI account. **Treat it like a password** — never paste it publicly, never put it in a screenshot, never commit it to public code. If one leaks, revoke it.
- **Cost (pay-as-you-go):** AI APIs usually charge **per usage**, measured in **tokens** (chunks of text — roughly ¾ of a word each; both your input and the AI's output count). It's often fractions of a cent per request, but **high volume adds up**. You set a **spending limit** in your API account so you can't get a surprise bill.
- **Rate limits:** how many requests you can make per minute. Automations should respect them (space out big batches).

> **Free vs. paid reality:** many no-code tools include a limited amount of AI processing on free tiers — great for learning and low volume. For higher volume or your own model, you'll use an API key with pay-as-you-go cost (your bill, directly with the provider — not included in your membership). Always set a spending cap.

**Security basics for any integration:**
- Give each tool only the **access it needs** (don't grant your whole account if it only needs one folder).
- Store keys in the tool's **secure credential field**, not in plain text.
- **Review connected apps** periodically; remove ones you don't use.

## Lesson 5.4 — When no-code vs. a small script

- **No-code (Zapier/Make/n8n):** best for connecting popular apps, standard triggers, and getting running fast. Covers the vast majority of business automations. **Start here. Stay here if it works.**
- **A small script (code):** worth it when you need something no-code can't do — custom logic, heavy data processing, a special integration, lower cost at very high volume, or a product you're building. More power, more responsibility (you maintain it).

**Decision rule:** can a no-code tool do it in a reasonable time? Then do that. Reach for code only when no-code genuinely can't, or when cost/scale demands it.

> **⌨️ Optional coding sidebar — calling an AI API with a tiny script**
> At its simplest, using an AI API in code is: (1) get an API key, (2) install the provider's library, (3) send a request with your prompt, (4) read the response. In Python it's a few lines — create a client with your key, call the "create message/completion" method with your prompt, print the result. The exact method names are in the provider's current docs (check them — they evolve). The same safety rules apply: keep the key secret (use an environment variable, never hard-code it), set a spending limit, and validate the output before using it. **Not required to pass** — a no-code automation fully satisfies the capstone.

## 🛠️ Hands-on exercise (40 min) — build one real automation
1. Pick a simple "when X → AI → destination" idea (triage inquiries, summarize new form entries, auto-draft a first reply to a draft folder).
2. In a free no-code tool, set the **trigger**, add an **AI step** with your prompt, and a **destination**.
3. **Test** it with one real (anonymized) example end to end.
4. If you used your own API key: set a **spending limit** and confirm the key is stored securely.
5. Add a **human checkpoint** if it touches anything customer-facing (e.g., draft replies, don't auto-send).

**You're done when** one automation runs end-to-end on a test input, with a spending cap (if using a key) and a human checkpoint where needed.

## ✅ Quiz (with answers & explanations)

**Q1. An API is…**
A) A type of AI model
B) A defined way for two pieces of software to talk to each other
C) A password
D) A spreadsheet
**Answer: B.** The "service window" apps use to request things from each other.

**Q2. Every automation has three parts:**
A) Prompt, model, price
B) Trigger, action(s), destination
C) Login, logout, refresh
D) Input, output, delete
**Answer: B.** Something starts it → AI/processing happens → result goes somewhere.

**Q3. An API key should be treated like…**
A) A public link to share
B) A password — kept secret, never public, revoked if leaked
C) A free coupon
D) A filename
**Answer: B.** It grants access to your account; keep it secret.

**Q4. AI API costs are usually based on…**
A) A flat monthly fee only
B) Usage measured in tokens (input + output), so volume matters; set a spending cap
C) Number of logins
D) Nothing — it's always free
**Answer: B.** Pay-per-use by tokens; cap your spend.

**Q5. True or false: You should reach for custom code before trying a no-code tool.**
**Answer: False.** Start no-code; use code only when no-code genuinely can't do it or scale/cost demands it.
